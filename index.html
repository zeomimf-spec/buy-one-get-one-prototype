买一送一交互链路优化方案

核心变更：分段开关切换现在喝/下次喝 + 平铺选品，减少弹窗一步到位

交互优化核心

❌ 旧交互
两个卡片单选方式 → 点卡片弹选品弹窗 → 选完关弹窗
→ 多一次弹窗，操作路径长
→
✅ 新交互
分段开关切换方式 → 下方直接平铺选赠品
→ 无弹窗，所见即所得，一步到位

用户操作流程对比

旧流程

1
选第1杯商品 + 规格
选商品、杯型、冰度、甜度
2
点「现在喝」或「下次喝」卡片
二选一，触发弹窗
3
弹窗里选赠品（3选1）
选完关闭弹窗
4
加入购物车
确认订单

新流程

1
选第1杯商品 + 规格
选商品、杯型、冰度、甜度（不变）
2
直接选赠品（平铺，点选即可）
默认现在喝模式，选完即生效
3
需要时切「下次喝」开关
赠品自动继承，券面自动更新
4
加入购物车
确认订单

下次喝模式：券是生椰拿铁专属兑换券。用户选了什么赠品，就囤什么券，核销时只能兑换这一款。

逻辑闭环与边界情况

🔄 切换开关 → 赠品继承

用户选了生椰拿铁，切到"下次喝"，赠品自动保留为生椰拿铁，卡片标签自动变成"兑换券·15天有效"。不需要重新选。

例：现在喝选了生椰拿铁 → 切下次喝 → 赠品还是生椰拿铁，只是从实物变成券

✏️ 换赠品 → 全局生效

不管在现在喝还是下次喝模式下，用户点选其他赠品，切换模式后赠品保持一致。

例：下次喝模式下点了云岭茉莉 → 切回现在喝 → 赠品自动变成云岭茉莉

🔀 购物车「更换赠送方式」

点击后弹出底部半屏弹窗，就是这个分段开关+平铺选品的同款面板，赠品选择保留，只切换交付形式。

一致性：详情页和购物车用同一套交互组件，体验统一

📦 数量 ×N → 赠品同步 ×N

买1送1按件计算。数量改为2时，赠品自动变为2杯生椰拿铁（现在喝）或2张生椰拿铁兑换券（下次喝）。

例：数量=2 → 买2杯杨枝甘露，送2杯生椰拿铁 或 送2张生椰拿铁兑换券

🚫 禁止逻辑漏洞

券的商品ID与所选赠品商品ID强制绑定，前后端双重校验，杜绝"选了生椰拿铁但发了通用券"的错配。

防护：下单时赠品ID = 券模板绑定的商品ID，不一致则拦截

💰 差价逻辑保留

原"最高送19元，超出补差价"逻辑保留。赠品选了18元的生椰拿铁，不需要补差价；如果选了20元的品，需要补2元差价。

说明：因为赠品依然是3选1，不同商品价格不同，所以补差价逻辑保留

业内最佳实践依据

设计维度 本方案做法 为什么是最佳实践
操作路径 去掉弹窗，平铺选品+分段开关 减少一次弹窗交互，所见即所得，用户决策效率更高
一致性 选什么赠品就囤什么券，完全对应 消除"我选了A赠品但囤了通用券能换啥"的预期落差
信息透明度 平铺展示所有选项，不用点开弹窗 用户一眼就能看到全部赠品选项，不用猜里面有什么
交互效率 开关切换即生效，赠品自动继承 切换方式不用重新选赠品，操作成本最低
UI一致性 保留原卡片选中态、配色体系 老用户无学习成本，视觉迭代平滑
