买一送一交互链路优化方案

核心变更：囤券从「通用代金券」改为「赠品专属兑换券」，选什么赠品就囤什么券

业务变更核心

❌ 旧逻辑
现在喝：3选1选赠品，当场拿走
下次喝：直接给19元通用代金券，不限品类，金额抵扣
→ 囤券 ≠ 赠品选品，用户拿券后还要纠结换什么
→
✅ 新逻辑
现在喝：依然3选1选赠品，当场拿走（不变）
下次喝：也3选1选赠品，囤成这杯赠品的专属兑换券
→ 囤券 = 赠品选品，选什么就囤什么，完全一致

逻辑闭环与边界情况

🔄 切换现在喝/下次喝 → 赠品保留

用户在现在喝选了生椰拿铁，切到下次喝时，赠品自动保留为生椰拿铁，券面自动更新为"生椰拿铁兑换券"。不需要重新选。

例：现在喝选了生椰拿铁 → 切到下次喝 → 券自动变成生椰拿铁专属券

✏️ 换赠品 → 券同步更新

不管在哪个方式下，用户重新选择赠品，另一个方式的赠品和券都同步更新。赠品选择是全局共享的。

例：下次喝模式下把赠品从生椰拿铁改成云岭茉莉 → 券自动变成云岭茉莉兑换券

🔀 购物车「更换赠送方式」

点击后弹出底部半屏弹窗，包含「现在喝」「下次喝」两个选项，赠品选择保留，只切换交付形式。

切换后：赠品行内容实时替换（实物↔专属券），赠品名称和规格不变

📦 数量 ×N → 赠品同步 ×N

买1送1按件计算。数量改为2时，赠品自动变为2杯生椰拿铁（现在喝）或2张生椰拿铁兑换券（下次喝）。

例：数量=2 → 买2杯杨枝甘露，送2杯生椰拿铁 或 送2张生椰拿铁兑换券

🚫 禁止逻辑漏洞

券的商品ID与赠品商品ID强制绑定，前后端双重校验，杜绝"选了生椰拿铁但发了通用券"的错配。

防护：下单时赠品ID = 券模板绑定的商品ID，不一致则拦截

💰 差价逻辑保留

原"最高送19元，超出补差价"逻辑保留。赠品选了18元的生椰拿铁，不需要补差价；如果选了20元的品，需要补2元差价。

说明：因为赠品依然是3选1，不同商品价格不同，所以补差价逻辑保留

业内最佳实践依据

设计维度 本方案做法 为什么是最佳实践
一致性 选什么赠品就囤什么券，完全对应 消除"我选了A赠品但囤了通用券能换啥"的预期落差
信息透明度 券面直接写赠品名称，不写"等值XX元" 用户清楚知道下次来喝什么，核销时不困惑
操作路径 赠品选一次，切换方式不用重选 减少重复操作，用户不用为同一个决策选两次
UI一致性 保留原卡片布局、选中态、配色体系 老用户无学习成本，视觉迭代平滑
容错性 赠品和券全局联动，自动同步 降低出错概率，避免券和赠品不匹配
