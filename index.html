逻辑闭环与边界情况

🔄 改第1杯规格 → 赠品/券同步

用户修改第1杯的杯型/冰度/甜度时，赠品（现在喝）和券（下次喝）自动同步更新。

例：杨枝甘露大杯→中杯，赠品自动变为中杯，券自动变为中杯兑换券。无需用户重新操作。

🔀 购物车「更换赠送方式」

点击后弹出底部半屏弹窗，包含「现在喝」「下次喝」两个选项，与详情页选择面板视觉一致。

切换后：赠品行内容实时替换（实物↔券），价格不变，购物车数量不变。

📦 数量 ×N → 赠品同步 ×N

买1送1是按件计算。数量改为2时，赠品自动变为2杯同款 / 2张兑换券。

例：数量=2 → 买2杯杨枝甘露，送2杯杨枝甘露（现在喝）或送2张兑换券（下次喝）。

⚠️ 第1杯换商品 → 赠品自动跟随

用户从活动区进入另一款活动商品时，赠品自动切换为新商品同款，无需用户重新选择赠送方式。

例：从杨枝甘露切到生椰拿铁 → 赠品自动变生椰拿铁，券自动变生椰拿铁兑换券。

🚫 禁止逻辑漏洞

原逻辑可能出现"买A送B但囤的是A券"的错配；新逻辑从UI层强制绑定，用户无操作路径产生错配。

防护：赠品商品ID = 第1杯商品ID，券模板ID = 第1杯商品ID专属，前后端双重校验。

💰 价格一致性

无论选「现在喝」还是「下次喝」，支付价格均为第1杯价格。赠品和券都是0元赠送，不产生补差价逻辑。

简化：原"最高送19元，超出补差价"逻辑取消，因为赠品就是同款，不存在差价问题。

业内最佳实践依据

设计维度 本方案做法 为什么是最佳实践
决策步骤 从5步减至3步，去掉选品弹窗 减少认知负荷，用户操作路径缩短40%，转化漏斗更短
预期一致性 买什么送什么，券也是同款 消除"赠品≠囤券"的预期落差，用户不会感到被套路
信息透明度 券面直接写商品名，不写"等值XX元" 用户清楚知道自己拿到了什么，核销时不困惑
UI一致性 保留原卡片布局、选中态、配色体系 老用户无学习成本，视觉迭代平滑
容错性 所有联动自动同步，无需用户手动维护 降低出错概率，减少客诉（如赠品选错商品）
